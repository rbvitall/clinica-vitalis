# Roteiro do vídeo — Clínica Vitalis (≤ 5 min)

Grave com o site aberto no navegador (de preferência já no GitHub Pages). Fale com calma;
o texto abaixo cabe em ~4min30. Entre colchetes = o que mostrar na tela.

---

**[0:00–0:25] Abertura**
"Olá, professor. Meu nome é Roberto Vital de Araujo, e este é o Projeto 01 da disciplina de
Programação e Desenvolvimento Web: uma landing page estática para uma clínica de saúde fictícia,
a Clínica Vitalis. Vou mostrar o site funcionando, o código e como ele foi publicado."

**[0:25–1:15] Hero e confiança**
[Mostre o topo da página; role bem devagar]
"A página abre com uma direção visual imersiva: os elementos se movem suavemente e ganham
profundidade conforme eu rolo — tudo em HTML, CSS e JavaScript puro, sem nenhuma biblioteca.
Logo na primeira dobra já aparecem os sinais de confiança: avaliação, número de pacientes e o
registro da equipe."

**[1:15–2:10] Serviços, primeira consulta e equipe**
[Role pelos serviços, depois 'primeira consulta', depois a equipe]
"Aqui estão os serviços, que avançam em profundidade ao rolar — são quatro, cada um com imagem
e descrição. Em seguida, o passo a passo da primeira consulta, para tranquilizar o paciente. E a
equipe fictícia: três profissionais, cada um com retrato, cargo e registro."

**[2:10–2:45] História, depoimentos e acessibilidade**
[Mostre 'Por que existimos', depoimentos, e clique no botão 'Modo acessível']
"A seção 'Por que existimos' dá a história da clínica, seguida dos depoimentos. E um diferencial:
este botão de Modo acessível desliga as animações e aumenta o contraste — além de o site já
respeitar automaticamente a preferência de menos movimento do sistema."

**[2:45–3:25] Formulário (requisito) e responsividade**
[Role até o contato; preencha o formulário e clique em Enviar; depois estreite a janela ou mostre no celular]
"O formulário de contato tem Nome, E-mail, Cidade e Estado. Ele é estático: valida no navegador e
mostra uma confirmação local, sem enviar nada a um servidor, como pede o enunciado. E a página é
totalmente responsiva — no celular tudo se reorganiza, sem rolagem horizontal."

**[3:25–4:15] O código e a organização**
[Abra o editor/repositório: mostre a estrutura de pastas e um trecho do build.py]
"Sobre a estrutura: o conteúdo fica em um arquivo JSON, e um script em Python, o build.py, gera o
index.html a partir desse JSON — então o Python entra de forma real, mas o site publicado não
depende dele. Tenho também um único H1, hierarquia de cabeçalhos, e todas as imagens com texto
alternativo. Os requisitos obrigatórios estão todos atendidos."

**[4:15–4:40] Publicação e fechamento**
[Mostre o site no link do GitHub Pages e a aba do repositório no GitHub]
"O projeto está no GitHub e publicado no GitHub Pages, acessível por este link. O repositório traz
um README com as instruções de execução. Era isso, professor — obrigado!"

---

## Dicas rápidas
- Grave com OBS, Loom ou o próprio celular. Feche abas/notificações antes.
- Publique no YouTube como **"não listado"** e cole o link no PDF de entrega.
- Se passar de 5 min, corte a parte do código (3:25–4:15) para uns 20 segundos.
